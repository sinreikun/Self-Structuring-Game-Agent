# 予測評価と候補の修正（0.4.1）

従来は、変化がないデータが多いと「予測不明」から「常に変化なし」への変更だけでも、予測誤差の改善として採用されることがありました。経験や仮説の件数だけから学習能力の獲得を判断できないため、評価とフィードバックを変更しました。

## 比較

入力後の変化率0.01を境とする既存の観測定義は維持します。評価は次の情報を保存・表示します。

- 変化あり／なしの件数と、それぞれの二乗誤差
- 変化ありの見逃し数、変化なしの誤反応数（確率0.5が判定境界）
- 両群を同じ重みで平均した均等損失
- 予測の分布幅、不明率、実行時間
- 常に0、0.5、1、および過去の全体頻度・入力別頻度の比較基準

頻度の比較基準は各経験の予測時点では過去のラベルだけを使い、当該経験を予測した後に更新します。評価データ全体から事前に頻度を計算しません。

採用には24件以上、変化あり・なし各4件以上を必要とします。現行と同一の予測、定数に近い予測、比較基準を均等損失0.01以上で上回らない候補は採用しません。現行との差も両群を同じ重みで比較し、実用差0.02と95%の標準誤差境界を超えること、不明率・実行時間の上限を満たすことを確認します。独立な時系列サンプルの近似であり、攻略能力を証明する統計ではありません。

過去経験の検証では、変化あり／なしの群ごとに平均誤差が0.02を超えて悪化しないことを確認します。過去の単一例だけによる拒否から、両群の平均による検証へ変更しました。

実機比較は32件から判定し、両群が不足している場合は最大128件まで観測します。不足のままなら改善未確認として記録し、候補・途中結果を保存します。片方しかない環境で改善や劣化を断定しません。保存経験の比較でも、最大128件または待機期限まで両群を集めます。

## 候補の説明と実際の出力

コードの命令名・learn関数の有無だけで採用可否を決めません。候補が新しい経験で実際にどんな予測を返すかを比較します。「学習する」と説明しながら現行と同じ出力だった場合や、比較基準を上回らなかった場合は、理由と候補コードを同じ研究ジョブの修正入力へ返します。

動作の改善がない候補の修正は同じ課題で最大2回とし、その後も候補・理由を保持して改善未確認として記録し、次の研究を妨げません。通信・構文エラー時の保存・再試行は既存の仕組みを維持します。比較件数が足りない場合は、実装不良としてコードの修正を要求しません。

修正に使った評価結果を次の候補が暗記して合格しないように、候補生成完了時点の最新経験IDを評価の開始境界とし、その後の新しい経験で比較します。

## 完了状態

watなしの有効な応答は観測・仮説のみの完了（observations_only）とし、実装改善が確認されたとは記録しません。比較不足（insufficient_evidence）、比較したが採用せず（evaluated_not_adopted）、修正待ち（behavior_repair）も区別します。既存の経験・研究・採用履歴は削除しません。旧形式レポートは過去記録として保持し、新しい評価を通過した扱いにはしません。

今回の変更は評価と候補生成へのフィードバックです。現在の個体へゲーム固有の意味や攻略、手作業の学習則を埋め込まず、有効な観測器・予測器・学習処理の獲得は次の実ゲーム記録で検証します。
