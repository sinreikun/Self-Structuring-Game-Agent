# 個体とモデルの管理（0.4.0）

上部タブは「研究室 / 個体管理 / 設定 / LLM管理 / 研究ノート / 能力接続図 / 開発者詳細」です。

## 個体

個体管理からロード・名前変更・完全複製・設定のみ複製・NEWBORN・比較・完全エクスポート・削除ができます。使用容量と研究件数はタブを開くか「容量を更新」で取得します。比較は件数・Revision・容量の比較であり、能力の優劣を証明する試験ではありません。

操作前にはSTOPして保存完了を待ちます。個体の切替・書き換え・複製・削除はゲーム実行と同じ排他ロックを使用し、処理途中の個体を別操作で変更できません。現在ロード中の個体は削除できません。別個体をロードしてから、確認画面で明示的に削除します。NEWBORNは旧個体を残します。共通LLM本体は個体削除の対象外です。

個体のロードで、その個体の保存設定（ゲーム、接続方法、許可キー、容量上限、研究間隔、知識モード、LLM識別情報・量子化・Context・Runtime・CPUスレッド数）を設定GUIへ反映します。管理LLMが保存済みならRuntimeを準備してロードします。外部ローカル接続なら接続確認します。ロード後はSTARTでゲームへの入力を開始します。Guidedの人間知識はExperiencedへ暗黙に変換しません。

既存キーと同じ順序のまま末尾へESCなどを追加する場合は同じ個体で継続できます。削除・並べ替えは学習済み入力番号の意味を変更するため拒否し、設定のみ複製かNEWBORNを案内します。別ゲームへの変更も同様です。

内部構成は既存データとの互換性と大量画像の不要コピーを避けるため、`experiments/<individual-id>/`を正式な個体フォルダとして使用します。

- `profile.json`: 固有ID、表示名、作成・最終使用日時、親個体、作成方法、登録後の稼働時間
- `settings.json`: 個体の設定と共通モデルへの参照
- `host/experience.sqlite3`: 経験、Knowledge、仮説、Reports、研究ジョブ・生成途中応答
- `host/checkpoint*`: Agent内部状態
- `agents/revisions/`: Agent Revision・自己改善履歴
- `evidence/`: 画像
- `host/host.log`: 個体ごとの実行ログ

0.3.2以前のフォルダも起動時に登録します。アクティブ個体は既存メタデータと最後の設定から復元します。旧版は過去の非アクティブ個体の設定を保存していなかったため、それらを自動復元したと扱いません。「設定を補完」で当時のゲーム・キー順序・知識モード・LLMを設定欄に合わせ、確認して保存してからロードしてください。元のDB・画像・チェックポイントは変更・削除しません。過去の正確な稼働時間やLLM利用履歴は遡って復元できません。

エクスポートは個体フォルダ全体を含み、SQLite backup APIで一貫したDBを保存します。モデル本体・Runtimeは含みません。エクスポート先は共通保存先の外を選択してください。コピー・削除・エクスポート時はリンクやジャンクションのあるデータを拒否します。

## モデル

LLM管理は常時表示の保存済み一覧・モデル検索・詳細から構成します。検索の「条件フィルタ」で用途・PC適合・規模・量子化・配布条件・並べ替えを選択できます。検索と導入には既存のGGUFモデルブラウザと完全性確認を使用します。手元のGGUF・外部ローカル接続も維持します。

モデル本体は`assets/model/<sha256>/artifact`、登録情報は`host/models/<sha256>.json`に保持し、個体へコピーしません。モデル名・量子化・サイズ・状態・Runtime・導入後検証・参照個体を表示します。配布元が不明な属性は未記録と表示し、品質やライセンスを推測して断定しません。

- 使用中: 動作中の個体が使用するモデルがRuntimeで稼働中
- スタンバイ: Runtimeへロード済み、個体は未実行または別モデルを指定
- 停止: 導入後の最小推論確認済みで、現在ロードされていない
- 未検証: 本体は保存されているが最小推論確認がない
- 異常: 本体がない、ロードエラー、Runtimeの予期しない終了

同時ロードは1モデルです。別モデルのスタンバイ時は前のRuntimeを停止してVRAMを解放します。自動GPU設定では既存のVRAM適合・CPUフォールバックを使用します。Context・CPUスレッド数・バックエンド設定を個体から実際の起動引数へ反映します。CPU/GPUを明示した場合は自動の別バックエンド置換を行いません。

「スタンバイ」は個体のモデル指定を変更しません。「使用する」で現在の個体へモデル構成を保存します。必要なモデルがない場合は別モデルへ自動置換せず、「同じモデルを検索 / 別モデルを選択 / キャンセル」を表示します。参照個体を残したままモデルを削除した場合も同じ案内になります。使用中・スタンバイ中のモデルは先に停止しないと削除できません。

## 共通設定

保存先、更新チャンネル、GUIテーマ・位置・レイアウト、Launcher、モデル本体、Runtime、診断機構は共通です。個体ロードでは切り替えません。保存容量上限は個体設定ですが、共通モデルを含めた保存先の総使用量に対して適用し、画面にもその旨を表示します。
