# ゲームと研究の復旧

ゲーム接続とHost全体の寿命を分離しました。ゲーム接続喪失は致命的なHostエラーとして扱わず、入力解放、途中経験の保存、再検出、起動、接続、画像取得確認、観測再開を繰り返します。待機中はwatchdogが自動でPAUSEしないようにし、STOPイベントを起動前・起動待ち・バックオフ中に確認します。

再起動の入口は初回設定の「起動・自動再起動用のゲーム／ランチャー」と起動オプションです。実際に接続したゲーム本体のEXE・PID・作成時刻・HWNDとは別に保持します。起動済みプロセスに接続する場合も、入口が未設定なら既知のゲーム本体を起動候補にします。起動の失敗では個体をNEWBORNにせず、同じ経験・チェックポイントを使用します。

プロセスはPIDだけで識別しません。既存の別インスタンスは除外し、実行ファイルと作成時刻で候補を絞ります。候補が複数の場合は勝手に選択して入力しません。ランチャーの系譜を追跡し、既知のゲーム本体が外部クライアントから起動される場合も新しい一意な本体を検出します。再接続できても画像取得に失敗する場合は復旧を続けます。

研究ジョブはpending/running/completeの永続状態を持ちます。LLMの途中出力はストリームから記録し、生成完了・形式エラー・出力上限・切断時の応答もproposalsへ残します。形式不正は具体的な検査結果を伴う修正待ち、通信・Runtime障害はエンジンの復旧対象です。研究に使った経験IDはジョブの保存状態へ保持し、待機中にGCで失われないようpinします。

ゲーム接続喪失中の実機比較は、候補ソースと比較途中の値を保存して再開待ちへ移します。異なるプロセス世代を同じ連続試行として混ぜず、復旧後の経験で比較をやり直します。WATの不正や実行時エラーでもソースを削除せず、保存した検査理由を使って修正します。科学的に改善しない候補は採用せず、記録として保存します。

STOPは入力と通信を止めます。保存済みの下書きは次回のExperienced開始時に再開できます。Host全体を閉じてもSQLiteに残るジョブを使用します。保存領域不足や研究監督処理の一時的な異常も、作業を保持して再試行します。外部アプリの認証や権限不足は復旧状態に理由を残し、認証情報の推測や無断の権限昇格は行いません。
