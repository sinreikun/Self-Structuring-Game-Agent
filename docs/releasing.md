# 更新と公開の方針

2026-11-01のユーザー指示「今後はテストが終わったらそのまま公開して」に基づき、更新作業は実装だけで終了せず、必要な検証、Windows EXEのビルド、リリース、署名付き本体更新情報の反映まで実施します。公開のたびにユーザーへ再確認する必要はありません。

既存の検証付き公開手順を使います。Windows CIで成功した同一コミットをタグ付けし、成果物のハッシュ・固定Launcherの不変性・更新署名を確認してから公開します。検証失敗は修正して再実行し、未検証のEXEを配布しません。公開後は実際のリリース資産と配信中マニフェストを照合し、ユーザーへ更新方法を報告します。

ユーザーが後から特定の更新を「公開しない」と指定した場合は、その指定を優先します。実際の権限不足や自動承認レビューの拒否が発生した場合は、拒否を迂回せず、理由と保留中の操作を報告します。


署名鍵の引継ぎ待ちなどで正式公開を完了できない場合は、release-requestのdraft_only=trueで、検証済みの同一コミットの資産を下書きへ揃えられます。この経路は公開済みリリースを変更せず、署名を省略して正式公開することもできません。署名済みManifestの準備後にdraft_onlyを削除またはfalseに戻すと、通常の署名検証付き公開に進みます。
