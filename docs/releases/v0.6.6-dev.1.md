# SelfStruct 0.6.6

実験情報が増えると研究入力がモデルのコンテキスト枠を超えて終了する問題を改善します。

提出された0.6.5診断の新規5 Jobでは、8実験・18入力を完了しましたが、事前登録・evaluate・能力候補生成には進んでいません。実験がある2 Jobは6回目／9回目の推論後にinput_budget_exceededで終了していました。0.6.5で追加した詳しい集計も入力増加の一因でした。

- 診断とJobには実験台帳の詳細を保持し、モデルには重複した実験数・Evidence・入力内訳や繰り返しの説明をまとめた専用の表示を渡します。
- 入力枠が厳しい場合は、過去の要求・別名・古い視覚配列や結果を段階的に圧縮します。実験した仮説の主張・事前登録・評価できない理由・残り予算は保持します。
- 最新の実画素やVision画像を優先します。画素を64値へ限定する場合も元の値をそのまま渡し、続きのoffsetを明示します。全結果は元のJobに保持し、省略を新しい観測や研究成功として数えません。
- 出力枠は可能なら2Kを確保します。最新画像と有効な応答が両立する場合は画像を保持します。最低限必要な入力も収まらない場合は従来どおり有限に保存終了し、上限を無視した送信や無限再試行はしません。
- 診断にcontext_budgetを追加し、入力数(input_count、モデルのtokenizerによる数)、出力予算、画像数、圧縮・省略数を確認できるようにしました。プロンプトや秘密情報は診断へ追加しません。

8K相当の入力枠を模した予算計数で、4実験対象・12観測・途中応答が重なるテストをVision/Text-only両方で行い、同じJobで再推論でき、最新の実視覚情報と実験対象を保持し、保存済み観測と実験台帳を変更しないことを検証しました。これは未知ゲームでの自律的な評価成功や能力獲得を保証する結果ではありません。

既存個体・モデル・Launcher 1.1.0を引き続き利用できます。更新後の診断でinput_budget_exceededの再発、context_budget、同じ登録済み仮説の反復実験とevaluateへの進展を確認してください。評価基準・実験上限は変更しません。
