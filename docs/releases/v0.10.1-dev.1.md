# SelfStruct 0.10.1 — job-context-budget-fix

## 変更

0.10.0 の新規個体（GEN-0010）実機観察で、研究ジョブが開始直後に input_budget_exceeded で終了し続ける不具合を確認しました。担当リンクの開始文脈が約30,732トークン（モデルの文脈枠8,192）まで膨らみ、モデルが一度も呼ばれていませんでした。本版はその文脈肥大を直します。

- 担当リンクの表示（prompt_view）で、ベースラインの代表フレーム（32×32×3 の画素配列）をテキストとして埋め込むのをやめました。ビューにはフレーム数とベースラインの活動領域（regions の要約）だけを載せます。画素配列はモデルがテキストでは使えず、視覚情報は画像配信で渡すのが本来の経路です。完全な記録は Job の台帳（link_context）にそのまま残ります。
- 文脈圧縮の段を追加しました。履歴の圧縮や古い結果の省略でも文脈枠に収まらない場合、担当リンクの表示を圧縮版（標本は最新1件のみ、根拠 ID は件数のみ、仮説・状態の本文は300字まで）に差し替えてから再構成します。即死ではなく段階的に縮める従来の方針（履歴ビューの段的トリミング）を、リンク文脈にも広げた形です。
- あわせて、ベースライン取得時に regions も読むようにし、表示側の要約に使います。

対象コミット：文脈修正（single_link / research）＋回帰テスト（test_context_budget_view）。

## 実機証拠と限界

観察の経緯：GEN-0010 のセッション1（123ステップ）では状況の自動登録とタグ付け（①）が動き、モデルが遷移主張と実験まで進みました。セッション2（1,023ステップ）では状況が12件・タグ901件まで育った一方、研究ジョブ11件すべてが input_budget_exceeded で終了し、②〜⑤は観察できませんでした。ペイロードの context_budget から、開始文脈の input_count ≈30,732 と主因（ベースラインのフレーム配列の文字列）を特定しています。GEN-0008 で 2026-11-05 に見た同種の連続死も同じ機構と判断できます。

ローカル全体回帰は 409 passed / 6 failed / 1 skipped（498.75秒）。失敗6件は変更前の素のツリーでも同一に失敗する環境依存の既知失敗（test_process_selection の実ウィンドウ系）で、新規失敗はありません。新規テスト3件（ベースライン配列を描画しないこと、圧縮ビューの縮小、元の記録を変更しないこと）は合格です。

限界：修正後に②〜⑤が現れるかは、公開後に同じ GEN-0010 で再観察して確認します。
