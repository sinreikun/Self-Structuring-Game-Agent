# SelfStruct 0.7.0

研究LLMの主目的を「研究対象の仕組みと達成すべき目的を理解し、その目的に沿って操作すること」、副目的を「人間向けに研究結果をまとめること」と明示しました。使える情報・操作・観測・道具の作り方を提示し、何を読み、どこを見て、何を試すかはLLMが選びます。画面変化率やBrier損失そのものをゲームの目的として扱いません。

## 必要な情報を取りに行く研究

経験、原画像と観測、仮説・事前登録、実験結果、研究履歴、研究メモ、研究結果を個体内の別々の保存領域に保持します。最初の入力は少数の経験メタデータ・索引・利用可能な手段です。保存済みBefore/After画像をLLMへ自動で先読みさせません。

- `memory_search`で関連記録の索引を検索し、`memory_read`で選んだ記録を少量ずつ取得します。見る必要がある画面は既存の`observe/compare`へ要求します。原画像は取り直したことにせず、保存済みIDから参照します。
- 正本のIDとSHA-256版を照合し、選んだ版の読取用スナップショットを同じJobに最大32件保持します。更新中も同じ版のページを読め、正本が変わればsource_changedと最新の版を返します。保持されていない古い版はstaleとなり、本文を混ぜません。保存容量が不足する場合は保持できないことを索引へ明示します。
- `memory_note`で短い作業課題・計画・未確認事項を外部保存できます。更新は版を照合して行い、別Jobや再起動後も検索できます。メモは統計的な支持・反証にはなりません。
- 目的が不明ならunknownとし、理解に必要な観察方法・領域・解像度・解析器・道具・入力をLLMが選びます。既存の安全な解析器生成・評価、WAT候補、ライブラリ申請の経路を利用できます。Hostはゲームの目的や操作の意味を補完しません。

## 人間向けの研究結果

`research_report`で、対象の目的とその確かさ、根拠付きの発見・仮説、未確認事項、次の方針を保存できます。これは研究の副目的です。GUIの研究ノートに「研究結果」「研究メモ」を追加し、個体をロードした状態で閲覧できます。研究結果はLLMの記述と明示し、画像変化の統計支持をゲームの意味・因果・目的達成の証明へ置き換えません。

## 入力枠と診断

提出された0.6.5診断の新規5 Jobでは8実験・18入力が完了しましたが、事前登録・evaluate・能力候補生成には進んでいません。実験がある2 Jobは6回目／9回目の推論後に入力枠超過で終了しました。未公開の0.6.6で進めていた圧縮修正を今回に統合し、さらに取得式へ変更しています。

Jobと診断には元の記録を保持し、LLMには直近の作業情報と要求された少量の記録を渡します。必要に応じて古い配列・結果を省略し、最新の実画素／画像を優先します。入力枠が不可約な情報でも足りなければ有限に保存終了します。既存の推論回数・要求数・入力数・統計評価・候補採用の上限や基準は緩めません。

診断にはメモリ取得元・版・ページ位置・本文ハッシュ・同じJobでの再推論、`context_budget`、研究方針の版、研究メモと人間向け研究結果を含めます。任意のプロンプト・ソース・秘密情報は追加しません。
