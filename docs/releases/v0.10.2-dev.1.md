# SelfStruct 0.10.2 — situation-mismatch-notice

## 変更

0.10.1 の本番稼働（GEN-0009、経験ゼロから開始）で、状況にアンカーされた主張が成熟できない構造を確認しました。仮説の主張（Wキー、確率0.8）は状況1にアンカーされていましたが、実験26試行はすべて別の状況（26と42）で実行され、評価は2回とも「対象状況での標本0件」で inconclusive になりました。状況フィルタ自体は正しく働いていますが、実験の実行時に「現在の状況 ≠ 主張の状況」をモデルも Host も照合していなかったため、標本にならない実験に入力予算が使われ続けていました。本版はその照合を入れます。

- 実験要求の実行前に、主張のアンカー（change_rate は situation、遷移主張は from_state）と現在の状況を照合します。現在の状況は、最新の経験イベントの状況タグ（無ければ開始フレームの同定）から Host が機械的に求めます。
- 不一致が確定した場合、実験は実行せず、構造化した通知（code: situation_mismatch、主張の状況と現在の状況の両方、理由）を無償で返します。モデルは現在の状況の主張を扱うか、主張の状況に戻ってから実験し直せます。
- 現在の状況が同定できない場合は止めません（同定の失敗で実験自体が飢えるのを避けるためです）。
- あわせて、実験文脈（experiment_context）に current_situation を載せ、モデルが要求前に現在地を確認できるようにしました。モデルへの指示文にも差し戻しの仕様を追記しています。

対象コミット：状況照合（transitions / research_actions）＋新規テスト（test_situation_mismatch）。

## 実機証拠と限界

観察の経緯：GEN-0009（経験ゼロ）の本番稼働で経験907件・状況10件・タグ563件・状況カード1件が育ち、ジョブ8件すべてが健全に終了しました。その一方で上記の不一致により、状況つき主張の評価が n=0 で止まることを実DBで確認しています。

ローカル全体回帰は 412 passed / 6 failed / 1 skipped（865.95秒）。失敗6件は変更前の素のツリーでも同一に失敗する環境依存の既知失敗（test_process_selection の実ウィンドウ系）で、新規失敗はありません。新規テスト3件（不一致時の無償差し戻しと同一状況での実行、現在状況が不明な場合に止めないこと、遷移主張は対象外であること）は合格です。修正コードでの GEN-0009 実機セッション（128ステップ）も健全でした（測定ジョブ20回呼び出し・research_limit 終了、開始文脈4,531トークン）。ただしそのセッションでは議題が主張未登録の仮説へ移っていたため、通知の実発火は起きていません。発火条件の検証は新規テストが担い、実発火の確認は今後の本番稼働に委ねます。

限界：通知を受けたモデルが実際に行動を変えるか（現在の状況の主張へ切り替える、状況が戻るまで待つ等）は、公開後の本番観察で確認します。
