# SelfStruct 0.6.5

実験結果の集計を、評価できる標本数と区別して研究LLMへ返します。研究上限で終了した場合も、最終実験を含む最新の診断情報を保存します。

提出された0.6.4診断の新規4 Jobでは、9実験・25入力を完了しました。0.6.4で追加した実験対象の保持は実機でも機能しています。一方、統計評価用の事前登録がなく、各対象の標本も少数で、明示的なevaluate・能力候補生成には進んでいません。Hostがゲームの意味や入力を推測して代行することはありません。

- 仮説ごとの入力別完了数・画像変化数を提示し、異なる入力を合算した観測数を統計標本数と混同しないようにしました。
- 事前登録の有無・登録入力・確率・登録時点、登録後に同じ入力で得られた標本数、不足数、条件による選別や入力不一致を明示します。未登録の過去結果への事後登録・標本の転用は行いません。
- 集計は現在Jobの記述であり、支持・反証の判定ではありません。evaluateを要求した場合は従来どおり同じ仮説に紐づく全Jobの実験を再検査します。評価・採用基準と実験上限は変更しません。
- 最後の推論で実験を実行して推論上限に達すると、experiment_contextとhypothesis_contextが実験前の状態で保存される問題を修正しました。提出診断では4件目の実験が集計から欠けていましたが、実験テーブル・action_historyには保存されており、元の結果は失われていません。

既存個体・モデル・Launcher 1.1.0を引き続き利用できます。更新後の実ゲームで、事前登録した同じ仮説への反復実験と評価へ進むかを診断で確認してください。追加観測や実験を自律的に選ぶこと、ゲームの有効な能力を獲得することは今回の変更だけでは保証しません。
