# SelfStruct 0.7.1

LLMへの研究方針に、対象が「人間が画面を見て入力し、状態を変えながら目的を達成するゲーム・対話型プログラム」であることを、Hostが与える既知の前提として追加しました。

観察と操作を通じて操作方法・ルール・目的を理解し、それに沿って行動するように指示します。情報不足時は記録の取得・追加観測・操作による確認を選び、画像解析や道具の作成はそのための手段と明示しました。具体的なゲーム名・攻略・ルール・目標・入力の意味を既知として補完することは引き続き禁止します。

人間向けの研究結果をまとめる副目的、取得式の記憶と目、既存Agentの通常操作とLLMの実験入力の分担、PAUSE/STOP・予算・評価基準は維持します。研究方針の版と新しい対象説明を診断へ記録します。

この説明によって実ゲームの目的理解や有効な操作が進むかは、更新後の実機診断で確認します。既存個体・モデル・Launcher 1.1.0を利用できます。

提出された0.7.0診断では6 Job・47推論、観測要求95件と記録検索27件が記録されています。観測は9件成功し、86件がエラーでした。原画像1600×900に対する1920×1080の範囲指定やnativeの画素面積上限超過があり、返す画素数limitを減らしても直せず再試行していました。また、経験IDをqueryへ指定すると入力キーだけを検索して空となり、存在する記録を見失っていました。入力枠超過は今回の診断では発生していません。

- 観測エラー時に実際のsource_size、対象Experience、最大画素数、box/size/limitの制約を構造化して返します。limitは返す値の数で、nativeの領域や変換解像度の面積を小さくしないことを明示します。どの範囲・解像度へ変えるかはLLMが選び、Hostは自動変更しません。
- experienceの数字だけのqueryは経験IDの完全一致検索として扱います。ref指定、入力名の文字列検索、cursor/watermarkによる絞込みも維持します。
- 同じJobで範囲エラー→実寸の取得→native面積上限の確認→LLMが選んだ解像度で実画像取得まで復帰するテストを、VisionとText-only双方で追加しました。実験・評価・人間向け報告へ進むことを実機で確認した結果ではありません。
