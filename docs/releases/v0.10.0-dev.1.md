# SelfStruct 0.10.0 — section2-whole-flow-skeleton

## 変更

方針文書 §2 の自然な順序（①状況の認識 → ②意味づけ → ③状況に根ざした探り → ④状況つき因果の知識 → ⑤編纂と自動化）を、浅く一通りつないだ骨格を実装しました。各段は最小形で、欠けている段が次の観察で分かる形にしてあります。

- ① 状況の認識：プレイ中に再出現する画面クラスタを Host が自動で未命名の状況として登録します（従来は候補の提示だけで、モデルの自発的な定義がなければプールが育ちませんでした）。各イベントには、その時点の状況タグを記録します（ジョブ外のプレイでも）。
- ② 意味づけ：状況カード（ラベル・場面種別・役割）を新設しました。モデルは describe_situation 操作で状況に意味を付けられます。未記述の状況はジョブの議題にも載ります。
- ③ 状況に根ざした探り：change_rate 型の主張は状況への固定（アンカー）を必須としました（ゲートで差し戻し、登録済み主張の内容を返して修正可能）。標本は「その状況で始まったもの」だけを数えます（タグ優先、無ければ代表プールで同定）。無入力ベースライン補正は従来どおりです。
- ④ 状況つき因果の知識：状況マップに、アンカー済み change_rate 主張の最終評価も載るようにしました。
- ⑤ 編纂：支持された遷移主張（事前登録・n≥16・supported）を技（skill）へ自動で編纂し、高速層の Player がその状況で技の入力を再利用します。使用結果（到達したか）は記録されます。技は単一入力のみです。
- 同定の性能：状況が常在すると毎ステップの同定コストが支配的になるため、イベント画像（書き込み後は不変）の画素・同定結果を Controller の Store にメモ化し、類似度計算をフラットバイト列で高速化しました（計算結果はビット同一）。grow は既存フレームとほぼ同一（≥0.999）のフレームの追加を省き、プールの trim もフラット計算に変えました。

対象コミット：b8508c7（骨格本体＋性能対策＋テスト）。

## 実機証拠と限界

ローカル全体回帰は 404 passed / 6 failed / 3 skipped（482.76秒）。失敗6件は変更前の素のツリーでも同一に失敗する環境依存の既知失敗（test_process_selection の実ウィンドウ系）で、新規失敗はありません。新規の骨格テスト7件（自動登録・タグ付け・状況カード・アンカー必須・標本フィルタ・技の編纂と使用）はすべて合格です。

限界：本番相当の観察（新規個体での実機セッションで①〜⑤の各段が現れるか）は公開後に行います。柱ごとの完成条件は、(1) 状況が自動で同定されイベントにタグが付く、(2) 状況に構造化された記述と意味が付く、(3) 状況からの探りがベースライン補正つきで走る、(4) 状況つき因果知識が評決つきで残る、(5) 検証済み因果から技が編纂され高速層が実際に使う、の5つです。残りの既知の継ぎ目：findings 経由の主張は未アンカーのまま登録されます（inline 経由で後付けのアンカー昇格は可能）。§5 の記述ベースの状態同一性、複数入力の技、司令塔層は未実装です。

## 配布検証の経緯

開発中の対象回帰では、骨格起因の不合格が4群見つかり、すべて直しました。(1) claims テーブルの列追加に伴うテスト側の位置指定 INSERT（名前付き列へ変更）。(2) 状況必須を文法（スキーマ）側で強制したため脚本化テストの主張が弾かれた問題は、ゲート側の構造化差し戻し（登録済み主張の提示つき）に移しました。(3) 履歴ビューの6,000字上限でモデルの直近の行動結果が空になる問題は、代表フレームの段的トリミングで解消しました。(4) 状況が常在することで同定コストが増え、30秒制限のライフサイクル試験と15秒制限の研究記憶試験が時間切れになった問題は、上記のメモ化・フラット化・grow の重複回避で解消しました（研究記憶の脚本研究は約37秒→約18秒、ライフサイクルは制限内で完走）。
