使用中のモデルと実際の推論方式を研究室に表示し、GPU/VRAM利用と研究用LLMの不具合を修正しました。

- 研究室の右上に使用モデル名、CPU/GPU、GPUへ転送した実際の層数を表示。外部接続では接続先のモデルIDと、GPU利用は接続先で管理することを表示します。
- Windowsで専用VRAMを持つGPUを検出した場合、公式llama.cpp Vulkan版をSHA-256検証付きで取得。既存CPUモデルも次のSTART時に移行し、モデルの再ダウンロードは不要です。VRAM使用層数は自動調整し、初期化ログの転送層数を確認してからGPU利用と表示します。
- GPU起動・取得・オフロード確認に失敗した場合は検証済みCPU版へ復帰し、復帰したことを表示します。NVIDIA/AMD等のVulkan対応ドライバーが必要です。GPU実機の有無と、実際のオフロード成功は区別します。
- 導入時の動作試験を研究用の完全出力検証から分離。短い試験の生成上限到達だけで、新しいモデルを不合格・ロールバックにしません。研究用の途中で切れたコードは引き続き実行しません。試験の終了理由・導入失敗・復帰情報を診断へ記録します。
- 研究入力から大量の評価メトリクスと冗長な経験一覧を除き、直近16件へ圧縮。AgentプログラムやABIは切断せず、管理Runtimeのトークン数を確認して入力と生成の枠を確保します。
- 推論期限を600秒へ変更し、STOP/終了時は接続中・入力処理中・応答待ちの通信を中断できます。開始時のGPU取得も中断対象です。思考切替に対応するモデルでは思考出力を無効にし、構造化された研究出力へ枠を使います。
- 診断ZIPに導入結果と実Runtime情報を追加。配布検証へ、実モデルを使う実際の研究プロンプトの完了確認を追加しました。

これはAgentの能力獲得を保証する更新ではありません。研究応答が完了しても、候補コードが不適合なら棄却します。局所領域の観測・解析方法の変更はAgentが提案・検証する対象で、Hostがゲーム知識や架空の能力を追加することはありません。

固定Launcher 1.0.0は同じファイルを継続使用します。対応GPUの実機でのVRAM利用量・速度は、利用者PCでの実行結果から確認が必要です。
