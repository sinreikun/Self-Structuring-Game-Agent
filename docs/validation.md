## 実施済み

最新の自動テストは38件成功、Windows専用I/Oの1件はスキップ。日本語GUIのテストはLinuxの仮想ディスプレイ上で実行した。Windowsのテストを成功として数えていない。

追加で[Windows CI](https://github.com/sinreikun/Self-Structuring-Game-Agent/actions/runs/41032409507)を実行し、38件成功・Linuxアーカイブ専用1件スキップを確認した。WindowsのGUI操作、テスト用ゲームウィンドウの画面取得・許可キー入力・入力解放・再起動を実行した。Windows EXEの生成と、生成物内の隔離評価用子プロセスを含む自己診断も成功した。

- 新しい公開済み環境へ保存された実装が復元され、依存環境を使って自動テストを再実行できた。
- 公式モデルのメタデータから不変の参照・サイズ・SHA-256を取得できた。
- llama.cppのソースのみの最新リリースを除き、公式バイナリ成果物を選ぶよう修正した。公式SHA-256がないものは使用しない。
- 公式Linux CPUエンジンとQwen2.5-Coder-1.5B-Instruct Q4_K_M（1,117,320,768バイト）を実際に取得・SHA-256照合し、ローカル推論の起動と応答を確認した。
- 取得済みのエンジン・モデルを再利用して再起動し、実モデルから研究用のJSON応答を生成・解析できた。
- 実モデルへ合成画面の経験を渡す研究試験も実施した。生成物に説明文を入れた不正な候補があり、隔離評価で棄却された。実モデルによる有用な自己改造の成功は未確認。
- 指示文の修正後、実際の非同期監督経路で研究ジョブ1件が完了し、応答を保存した。この実行では新しい改善コードの提案はなく、候補採用の成功としては数えていない。
- Linux用単体梱包物で、保存・再開と隔離評価子プロセスの起動を含むスモークテストを確認した。仮想画面上では梱包物のGUI・Tk・同梱資源・Wasmtime初期化も確認した。
- 原画像の保持、入力記録、再開、出所と仮説の分離、独立経験での仮説反証、隔離コードの燃料・メモリ制限、許可外アクセス拒否を自動検証した。
- 合成画面の結合試験で、非同期研究→コード候補→独立Replay→過去経験での回帰検査→実入力の交互比較→採用までを確認した。この試験の研究提案は制御されたテスト用応答であり、実モデルの自己改善能力を証明するものではない。
- 不適合候補の棄却と、実行異常を起こす候補からの安定世代への復旧後に経験収集が続くことを確認した。
- 実モデルの取得・推論試験と、合成ゲームによる自己改善結合試験は別の検証である。実モデルが未知ゲームで有用なコードを生成・改善できたという主張はしない。

## 未検証・配布上の条件

| 条件 | 現在の状態 |
| --- | --- |
| Windowsの画面取得・入力・入力解放・再起動 | Windows CIのテスト用ウィンドウで確認。各利用者の実ゲーム・描画環境での確認は別途必要 |
| Windows単体EXEの生成と起動 | Windows CIで生成・梱包後自己診断を確認 |
| 署名済み本体更新の取得・置換・失敗時復旧 | 実装あり。公開鍵・実配布元が未設定のため実配布では未検証 |
| 未知ゲームでの長時間無人稼働 | 未検証 |
| 複数ゲームの概念・技能形成と転移 | 未検証。現在の評価は主に画面変化の予測であり、ゲーム進行の成功指標ではない |
| ゲームを別プロセスへ渡すランチャー | 非対応。直接起動したPIDのウィンドウだけを対象とする |
| 背面での入力・取得 | ウィンドウ宛て入力と隔離WorkerによるPrintWindow取得へ変更。最小化は対象外。Raw Input専用などのゲームは非対応 |
| あらゆる描画方式・非表示ウィンドウ | 保証しない。デスクトップ画素や全体キーボード入力への代替は行わない |
| 外部ネイティブDLLの自動採用 | Agentへ直接ロードする経路は提供していない |

自動テストの成功だけで完成版や長期安定性を宣言しません。Windows用の配布物、署名付き更新元、実機I/Oと長時間運転の結果がそろうまでは開発版として扱います。
