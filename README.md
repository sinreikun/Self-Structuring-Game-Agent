# 自己発達型ゲームAI — SelfStruct

未知のゲームの画面と、許可された入力だけから経験を集め、自分の観測・予測方法を改善するための自律研究アプリケーションです。ゲーム固有の攻略方法や「敵」「HP」などの意味を初期状態へ埋め込みません。

**0.5以降への移行では、配布ページからSelfStructLauncher.exe（Launcher 1.1.0）を一度取得し直してください。署名鍵の移行に伴う変更で、既存の個体・経験・モデルは引き続き使用できます。**

現在は開発版です。[GitHub Releases](https://github.com/sinreikun/Self-Structuring-Game-Agent/releases)からWindows向けの固定Launcher EXEと自動管理される本体を配布します。Windows CIでGUI操作・テスト用ウィンドウの画面取得と入力・再起動・梱包後の自己診断を確認しています。未知のゲームを理解・攻略できることや、長時間の無人稼働が保証された完成版ではありません。本体更新にはEd25519署名とSHA-256の検証を使用します。

## 初回設定と使い方

Windows配布版では `SelfStructLauncher.exe` を起動し、「初回設定」で次を設定します。通常利用者がPythonや別のLLMサーバーを導入する必要がない構成です。

1. 「接続方法」を選びます。直接起動する場合はゲームの実行ファイル、ランチャー経由の場合は「ランチャーから起動」と起動用EXEを指定します。起動済みなら「起動中から選択」でゲーム本体のプロセスまたはウィンドウを選びます。アプリ名・番号・ウィンドウ名で検索できます。
2. ゲーム本体を含まない専用の保存フォルダと、容量上限を指定します。
3. 送信を許可するキーを設定します。通常の英数字・方向キー・Tab・テンキーのNum0〜Num9などを指定できます。大文字・小文字は区別しません。テンキーは上段の数字キーとは別の入力として扱います。
4. ローカルLLMを選び「自動導入」を押します。公式配布元のエンジンとモデルを取得し、完全性を確認して推論試験を行います。初回はネット接続と数GBの空き容量が必要です。軽量モデルでもコード生成の成功は保証されず、不適合の候補は棄却されます。
5. Newborn（新規個体）かExperienced（以前の個体を継続）を選び、設定を保存します。
6. STARTを押します。対象ゲームが背面になったり他のウィンドウで覆われたりしても継続します。別のアプリや対象ゲームをユーザーが操作しても自動停止しません。最小化は対応対象外です。元の大きさに戻すと自動で継続します。

| 操作 | 動作 |
| --- | --- |
| START | 開始、または一時停止から再開 |
| PAUSE | 入力を解放し、経験収集を一時停止 |
| STOP | 実験を終了し、経験と内部状態を保存 |
| NEWBORN | 次の開始でゲーム固有経験のない個体を作成。以前のデータは保持 |
| 診断ZIPをコピー | 作業フォルダ内に診断を保存し、ZIPファイルとしてコピー |

START後は設定と内部状態を保存します。STOPせずアプリを閉じた場合、次回起動時は保存個体で自動再開を試みます。PC起動時の自動起動登録は行いません。

研究室では現在画面・入力前後の比較・差分画像を切り替えられます。研究ノートでは観測、仮説、支持、反証を区別します。コードや生ログは「開発者詳細」に分けています。

「ランチャーから起動」では、ランチャー自身の画面へ入力せず、同じ起動から生まれたゲーム本体の子・孫プロセスを追跡します。ランチャーが先に終了しても本体の検出を続けます。ウィンドウ名を指定する場合は、ランチャーではなくゲーム本体の名前を指定してください。既に稼働するサービスなど、子プロセスとして検出できない経路で起動する場合も、ゲームを起動してから「起動中から選択」で接続できます。

既存プロセスへの接続では、STOPや接続復旧でそのゲームを強制終了しません。選択時の起動時刻も照合し、同じ番号を再利用した別プロセスには接続しません。選択したプロセスが終了した場合は、一覧から選択し直してください。実行ファイル・ランチャーからこのアプリが起動したゲームは、従来どおり自動復旧時に再起動できます。

入力は対象ウィンドウだけへ送信し、PC全体のキーボード入力や前面ウィンドウの切り替えは行いません。停止はGUIのPAUSE / STOPを使用してください。従来のグローバルなF12停止はありません。

背面操作はウィンドウ宛てのキーメッセージに対応するゲームが対象です。Raw Inputや実キーボード状態の直接取得だけを使うゲーム、背面で処理を止めるゲーム、画面取得を制限する描画方式では動作しない場合があります。他アプリへ入力が漏れる全体入力への自動切り替えは行いません。

## 復旧と保存

Agentの変更は、有限の隔離実行、新しい独立経験での予測評価、過去経験の回帰検査、実入力での交互比較を通した後にだけ採用します。候補の自己申告だけでは採用しません。予測を採点する前に結果画像を渡さない設計です。

実行異常時は入力を解放し、安定世代へ戻します。ゲーム再起動の試行回数にも上限があります。容量増加時には古い冗長経験を自動整理し、研究・評価・異常時の根拠を保護します。画像は完全一致の内容ハッシュで共有します。保護対象で枠が尽きた場合のみ停止します。

データは保存先の `experiments` 以下で個体ごとに分離されます。Host設定、原画像、Agent世代、作業領域、推論エンジン、モデル、本体更新は別の領域へ保存します。AgentにはOS・ネットワーク・ネイティブDLLへの直接アクセスを与えません。

ゲーム画面の理解不足や仮説の反証は研究対象です。一方、ゲーム実行ファイルの消失、ディスク・権限の異常、推論エンジンの長期停止、有限回の復旧に失敗した場合は、実験装置の確認が必要です。診断ZIPには画面画像が含まれるため、第三者へ渡す前に内容を確認してください。

## 検証と配布の状態

検証結果と未達条件は [検証記録](docs/validation.md)、設計は [アーキテクチャ](docs/architecture.md) に記載しています。要件原文も [基本仕様](docs/requirements-core.md) と [配布仕様](docs/requirements-distribution.md) に保存しています。

Windows EXEはWindows上で生成します。GitHub Actionsの「Test and Windows EXE」はテスト・梱包後に成果物を保存する構成で、リリースへの公開は別に行います。固定Launcherが公式の署名付きManifestを確認して本体を更新します。

## 長時間運転・診断・本体更新（0.2）

研究室は暗色の観測コンソールになりました。現在の行動・結果・次の予定、LLM状態、日本語タイムライン、保存使用量を表示します。緑のLLM表示は実際の推論要求中だけです。評価・復旧・エラーは別の状態です。研究ノートは「現在／発見／仮説／支持／反証／自己改善」に分かれます。観測領域の要求があればプレビューに枠を表示します。能力接続図はAgentの `op=describe` による自己記述だけを表示し、未報告の能力をHostが創作しません。

「診断ZIPをコピー」で、設定した作業フォルダの `exports/diagnostics/` にZIPを作成し、WindowsのCF_HDROP形式でファイルとしてコピーします。作成後は添付欄へ貼り付けられます。貼り付け対応は提出先アプリにも依存します。失敗してもZIPは残ります。モデル・エンジン・全経験は含めず、最大24MiBの入力データ、直近の代表画像・診断用DB抜粋・ログ・評価・GC履歴を収録します。認証項目は削除しユーザーパスを匿名化しますが、ゲーム画面に表示された個人情報は画像に残り得るため、提出前に内容を確認してください。診断の自動送信はありません。

保存容量はモデル・エンジンを含む作業フォルダ全体が対象です。80%でGC、90%で積極整理、95%から通常画像の保存を抑え、最後の5%を研究・復旧・診断用に残します。仮説・支持・反証・候補評価・異常前後の根拠は保護します。直近の研究用窓と代表遷移を残し、古い冗長経験を条件・結果・期間・件数の統計へ集約します。集約した経験は生画像がある経験としてReplayへ渡しません。保護対象そのものが上限を使い切った場合には、安全のため停止します。無制限保存を保証するものではありません。

配布入口は **SelfStructLauncher.exe** です。以後は同じLauncherを使ってください。公式のEd25519署名付きManifestを確認し、本体を `runtime/versions/<version>-<digest>/` に保存します。起動確認後にcurrent／last-known-goodを切り替え、失敗時は旧版、オフライン時は検証済みローカル版を起動します。初回のみ接続が必要です。Applicationの更新領域とAgentの `experiments/` は別です。既存のSelfStruct.exeから移行しても保存先は変わりません。ApplicationはAuthenticode未署名です。

ウィンドウ位置・通常サイズ・最大化・分割位置・タブはバージョン付きLayoutに保存します。モニタが外れた場合は現在の表示領域に補正します。配置のUI IDはゲーム知識・Agentデータには含めません。

署名付き本体更新の公開手順は [更新配布](docs/application-update.md)、保持規則と検証上の限界は [設計](docs/architecture.md)・[検証](docs/validation.md) を参照してください。

### GGUF検索とPC負荷表示（0.3）

研究室はゲーム画面を左に大きく表示し、右側で現在の研究・入力履歴・実処理のLIVE TRACE・能力接続図・PC全体の負荷を確認できます。初回設定では固定2択に代わり、GGUFモデルを検索し、量子化・容量・PC適合・ライセンスを確認してそのまま導入できます。手元のGGUFや外部ローカル接続先も引き続き利用できます。[検索・適合判定の範囲と制限](docs/model-browser.md)を参照してください。固定Launcher 1.0.0は更新不要です。


### 共通の目と視覚研究（0.5）

AgentとScientistは、同じ画面Evidenceを領域・解像度・RGB/輝度・画素・差分・統計・形状で調べ、情報不足なら追加観測できます。Runtimeが画像入力対応を明示する場合は、選んだ画像だけを直接渡します。非Visionモデルにも同じEvidenceへのアクセスがあります。

自作の汎用演算パイプラインは個体の解析器として保存し、新しい経験で独立評価を通した後に通常利用します。モデルを替えても個体の視覚資産は保持されます。Hostがゲームの意味を与えたり、Vision出力を確定事実にしたりはしません。研究室のAI注目領域・LIVE TRACE・能力接続図は実際の要求と登録資産に連動します。[API・評価・保存・制限](docs/visual-access.md)を参照してください。


### 研究の修正ループ復旧（0.5.1）

同じWAT構文エラーの無期限再試行を修正しました。候補を先に検査し、修正が上限に達した研究は候補と記録を残して終了します。旧版で停滞した保留Jobも自動で処理し、既存の個体で新しい研究へ進みます。Scientistへ初回からBefore/Afterの実画素または選択画像を渡し、追加観測も継続できます。[修正内容と検証範囲](docs/research-recovery.md)を参照してください。
