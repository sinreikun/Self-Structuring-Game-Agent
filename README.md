# 自己発達型ゲームAI — SelfStruct

未知のゲームの画面と、許可された入力だけから経験を集め、自分の観測・予測方法を改善するための自律研究アプリケーションです。ゲーム固有の攻略方法や「敵」「HP」などの意味を初期状態へ埋め込みません。

現在は開発版です。[GitHub Releases](https://github.com/sinreikun/Self-Structuring-Game-Agent/releases)からWindows向け単体EXEを配布します。Windows CIでGUI操作・テスト用ウィンドウの画面取得と入力・再起動・梱包後の自己診断を確認しています。未知のゲームを理解・攻略できることや、長時間の無人稼働が保証された完成版ではありません。署名付き本体更新は未設定です。

## 初回設定と使い方

Windows配布版では `SelfStruct.exe` を起動し、「初回設定」で次を設定します。通常利用者がPythonや別のLLMサーバーを導入する必要がない構成です。

1. 対象ゲームの実行ファイルと、必要に応じてウィンドウ名・起動オプションを選びます。別のランチャーから子プロセスを起動するゲームには現在対応していません。
2. ゲーム本体を含まない専用の保存フォルダと、容量上限を指定します。
3. 送信を許可するキーを設定します。通常の英数字・方向キーなどだけを許可できます。
4. ローカルLLMを選び「自動導入」を押します。公式配布元のエンジンとモデルを取得し、完全性を確認して推論試験を行います。初回はネット接続と数GBの空き容量が必要です。軽量モデルでもコード生成の成功は保証されず、不適合の候補は棄却されます。
5. Newborn（新規個体）かExperienced（以前の個体を継続）を選び、設定を保存します。
6. STARTを押します。対象ゲームが背面になったり他のウィンドウで覆われたりしても継続します。別のアプリや対象ゲームをユーザーが操作しても自動停止しません。最小化は対応対象外です。元の大きさに戻すと自動で継続します。

| 操作 | 動作 |
| --- | --- |
| START | 開始、または一時停止から再開 |
| PAUSE | 入力を解放し、経験収集を一時停止 |
| STOP | 実験を終了し、経験と内部状態を保存 |
| NEWBORN | 次の開始でゲーム固有経験のない個体を作成。以前のデータは保持 |
| EXPORT | 研究ノート・診断DB・世代情報・最近の根拠画像をまとめて保存 |

START後は設定と内部状態を保存します。STOPせずアプリを閉じた場合、次回起動時は保存個体で自動再開を試みます。PC起動時の自動起動登録は行いません。

研究室では現在画面・入力前後の比較・差分画像を切り替えられます。研究ノートでは観測、仮説、支持、反証を区別します。コードや生ログは「開発者詳細」に分けています。

入力は対象ウィンドウだけへ送信し、PC全体のキーボード入力や前面ウィンドウの切り替えは行いません。停止はGUIのPAUSE / STOPを使用してください。従来のグローバルなF12停止はありません。

背面操作はウィンドウ宛てのキーメッセージに対応するゲームが対象です。Raw Inputや実キーボード状態の直接取得だけを使うゲーム、背面で処理を止めるゲーム、画面取得を制限する描画方式では動作しない場合があります。他アプリへ入力が漏れる全体入力への自動切り替えは行いません。

## 復旧と保存

Agentの変更は、有限の隔離実行、新しい独立経験での予測評価、過去経験の回帰検査、実入力での交互比較を通した後にだけ採用します。候補の自己申告だけでは採用しません。予測を採点する前に結果画像を渡さない設計です。

実行異常時は入力を解放し、安定世代へ戻します。ゲーム再起動の試行回数にも上限があります。容量不足では根拠画像を削除せず停止します。画像は内容が同じ場合だけ共有し、元の経験への参照を保持します。

データは保存先の `experiments` 以下で個体ごとに分離されます。Host設定、原画像、Agent世代、作業領域、推論エンジン、モデル、本体更新は別の領域へ保存します。AgentにはOS・ネットワーク・ネイティブDLLへの直接アクセスを与えません。

ゲーム画面の理解不足や仮説の反証は研究対象です。一方、ゲーム実行ファイルの消失、ディスク・権限の異常、推論エンジンの長期停止、有限回の復旧に失敗した場合は、実験装置の確認が必要です。EXPORTには画面画像が含まれるため、第三者へ渡す前に内容を確認してください。

## 検証と配布の状態

検証結果と未達条件は [検証記録](docs/validation.md)、設計は [アーキテクチャ](docs/architecture.md) に記載しています。要件原文も [基本仕様](docs/requirements-core.md) と [配布仕様](docs/requirements-distribution.md) に保存しています。

Windows EXEはWindows上で生成します。GitHub Actionsの「Test and Windows EXE」はテスト・梱包後に成果物を保存する構成で、リリースへの公開は別に行います。公式更新は署名鍵が設定されるまで利用できません。

<details>
<summary>開発者向け：テストとビルド</summary>

Python 3.12以降の64bit環境を使用します。Windowsでは標準のPython配布に含まれるTkを使用します。

```sh
python -m pip install -e '.[dev]'
python -m pytest -q
python -m selfstruct --self-test
python tools/build.py
```

Windowsでは `dist/SelfStruct.exe`、Linuxでは `dist/SelfStruct` を生成します。Linux生成物はWindowsで使用できません。梱包後にも `--self-test` を実行してください。GUIテストにはディスプレイが必要です。Linux上のWindows I/Oテストはスキップされます。

通常起動は `python -m selfstruct` です。LinuxにもCPU推論エンジンの取得・検証経路を用意していますが、実ゲームのI/OはWindows専用です。

管理済みモデルを使う研究結合試験は `tools/check_real_research.py` で実行できます。モデル保存先を `--model-root`、実験記録の専用保存先を `--experiment-root` で指定します。合成画面を使う試験であり、未知ゲームへの学習成功を示すものではありません。

本体更新の配布担当者は `src/selfstruct/release.py` に公開鍵・配布先を設定し、`tools/sign_manifest.py` で更新情報へ署名します。秘密鍵をソースや通常UIへ入れないでください。依存ライブラリのライセンス文書は梱包時に収集します。

</details>
